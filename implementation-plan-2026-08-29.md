## №28 — Длительность нахождения записи «Точки продаж» на стадии согласования (CRM_34, 1084)

- Та же техническая проблема, что уже описана для Договоров (BACKLOG.md п.17/18):
  `updatedTime` двигается от любой правки карточки, не только от смены стадии — не годится
  как источник даты входа в стадию.
- Решение: новое UF-поле `ufCrm34StageEnteredDate` (date) + бизнес-правило Б24 «При смене
  статуса — записать текущую дату в поле» (настраивается в UI по одному на каждую стадию,
  через `crm.type.update`+`userfieldconfig.add` для самого поля создать можно по API, правила
  переходов — только через UI).
- На дашборде (пока непонятно, на каком — «Активность»? отдельная карточка на `/report`?) —
  показывать «дней на текущей стадии» = сегодня − `ufCrm34StageEnteredDate`.
- **Уточнить у владельца:** нужен ли этот трекинг именно для «Точек продаж», или (как и в
  BACKLOG.md п.18) сначала разобраться с тем же вопросом для Договоров, раз паттерн общий —
  может, стоит сделать один раз универсально, не по одному СП за раз.
