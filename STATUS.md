## Локальное приложение Б24 «Отчёты Потолкуем» (23.08.2026 — 01.08.2026)

Дашборды встроены как **локальное приложение Б24** — открываются из левого меню Б24
(«Приложения») внутри iframe, авторизация по правам пользователя портала вместо отдельного
логина. Basic Auth (`admin`/`director`) сохранён как fallback для прямого захода на
`db-talk.bobp.ru` вне портала.

**Как это работает:** Б24 при открытии приложения шлёт POST на `/bx/entry`. Поля `DOMAIN` там
**нет** — вместо него `member_id` (постоянный ID портала, не меняется в отличие от домена) и
`SERVER_ENDPOINT` (общий OAuth-шлюз `oauth.bitrix24.tech`, который для этого портала не отдаёт
`user.current`/`profile` — рабочий вызов только напрямую на домен портала, `SERVER_ENDPOINT`
оставлен резервным вариантом). `AUTH_ID` используется один раз — вызывается метод `profile`,
чтобы узнать, кто открыл приложение, и сразу забывается (полноценный OAuth token-exchange не
нужен — данные для дашбордов как и раньше идут через постоянный `B24_WEBHOOK`). Личность/права
дальше живут в собственном JWT (`?bxt=...`, 2 часа), который пробрасывается по ссылкам и
формам внутри iframe — cookie не используются (блокируются как third-party в iframe на чужом
домене). **Важно:** любой `res.redirect(...)` на сервере обязан пробрасывать `bxt` через
`withBxt()` (index.js) — иначе сессия рвётся на первом же редиректе и падает на Basic Auth.

| Параметр | Значение |
|---|---|
| Тип приложения в Б24 | Локальное, серверное |
| Handler URL | `https://db-talk.bobp.ru/bx/entry` |
| Права (scope) | `user_brief` (только опознать пользователя, `user.current`/`profile` его принимают) |
| client_id / client_secret | в `.env` на проде (`BX_CLIENT_ID`/`BX_CLIENT_SECRET`), в текущем потоке не используются в коде — сохранены на будущее |
| member_id портала | в `.env` (`BX_MEMBER_ID`) — используется для проверки, что запрос пришёл именно с этого портала |
| Кто видит «Расходы руководству» | id 18 (Анна Агеева-Дзукаева), 116 (Александр Дзукаев), 12 (Мария Цакунова), 134 (Александр Жуков) — список в `BX_DIRECTOR_IDS` |

Новые файлы: `report-app/bx-auth.js` (мост Б24 → сессия), `report-app/bx-embed.js`
(bootstrap для iframe: `BX24.fitWindow()`, проброс `?bxt=` по ссылкам/формам), `report-app/nav.js`
(единая панель навигации между всеми 7 дашбордами — единственное место, где меняется список
ссылок; раньше каждый `render-*.js` хранил свой набор ссылок вручную, и он расходился — где-то
не было ссылки на Склад, где-то на SMM/Задачи).

**Ручной шаг (сделать в Б24, потом задеплоить код):** `potolkuem.bitrix24.ru` → Настройки →
Разработчикам → Другое → Локальные приложения → Добавить → тип «Серверное» → права `user_brief`
→ Handler URL как выше → скопировать `client_id`/`client_secret` в `.env` на проде →
после первого открытия выдать доступ нужным сотрудникам на вкладке «Права» приложения.
