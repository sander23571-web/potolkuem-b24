## 1. Что такое дашборд технически

`https://potolkuem-dashboard.artprogress.tech/` — статически отрендеренная HTML-страница + подгружаемые
JSON-файлы (`public-data/*.json`, до 5 МБ) и статичные HTML-отчёты (`reports/*.html`, до 370 КБ). Первая
загрузка страницы показывает карточки KPI с прочерками «—» — реальные цифры лежат в `public-data/overview.json`
и `public-data/panels/seo.json`, которые подтягиваются JS-скриптом на клиенте (простой `curl` без выполнения
JS их не видит; я вытащил файлы напрямую по путям, зашитым в bootstrap-скрипте страницы).

Источники, которые дашборд сам заявляет (`shared.json → sources`):
- SEO-панель: Яндекс.Вебмастер + Яндекс.Метрика
- Traffic/Metrica: Яндекс.Метрика
- Paid traffic: API Яндекс.Директа + API VK Рекламы
- Структура: sitemap + технический обход + граф ссылок

### 4. План внедрения — приоритеты P1/P2

**P1 (8 страниц)** — Главная, Вселенная игр/каталог, Классика, Красноречие, Дипломатия, Рекламная пауза,
Бизнесу/корпоративные мероприятия, Клуб/прийти поиграть.

**P2 (12 страниц)** — Гастрономия, Сомелье, Мода, Музыка, Кинематограф, Мировая литература (страница ещё
не создана — `future:/mirovaya-literatura`), Архитектура, Живопись, Дизайн и ремесла, Сказки, Наука, Диалекты.

Для каждой P1-страницы указан конкретный технический фокус, например:
- Каталог (`/universe`): добавить H1, вступление категории, карточки, внутренние ссылки на все игры.
- Рекламная пауза: заменить H1 на специфичный про продажи/питчи.
- Клуб: заменить H1 на «клуб в Москве», добавить адрес/формат/FAQ.
- Главная: технических блокеров нет, доработать релевантность под SERP.

Пример Keyso/SERP-сигнала (Главная): 199 строк ранжирования, лучшая позиция — 1, 5 запросов в топ-10,
14 — на 11–20 месте, конкуренты в выдаче — ozon.ru, tr-page.yandex.ru, vsova.ru.

### Контроль качества — что сам аудит признаёт незакрытым

12 строк `pass`, 8 строк `warn`, 0 `fail`. Ключевые `warn`:
- Часть ключей не имеет точной (exact) частотности Wordstat — «Безопасный темп» для них намеренно
  не назначен («не планировать»).
- Broad-ключи с неоднозначным интентом («игра про фильмы», «игра про книги», «игра про моду», «игра про
  еду») оставлены в статусе review без темпа продвижения — высокая broad-частотность не означает, что
  можно разгонять трафик.
- P2/future-страницы (Сказки, Мировая литература) — без действующей посадочной, продвигать нечего.
- Финальная строка аудита: **«Файл не должен использоваться как финальный traffic-plan без проверки
  warn-строк»** — сама агентство честно помечает документ как черновой в проблемных местах, не выдаёт
  его за 100%-готовый.

Дата QC-аудита — 27.05.2026, тогда как метрики/трафик по посадочным обновлены позже (до 29.07/02.08) —
сам аудит может быть частично устаревшим относительно текущих данных вкладок.

## 5. Рекомендация — стоит ли внедрять и в каком порядке

Workbook — это готовый, детализированный бэклог, а не абстрактная стратегия. Рекомендуемый порядок:

1. **Сначала 8 страниц P1** — минимальные правки (title/H1/description по готовым рекомендациям из
   вкладки «SEO ТЗ по страницам» + блоки из «Контент-брифа»). Низкий риск: почти везде отмечено
   «технических блокеров нет», меняется только контент/мета, не структура.
2. **Не трогать /diplomatiya без владельца интента** — сам QC отмечает риск каннибализации/чужого
   продукта Diplomacy на этой странице; нужна проверка перед продвижением.
3. **«Безопасное усиление» — использовать план темпа как есть**, не форсировать ключи, помеченные
   «не планировать» — это единственная вкладка с явными защитными ограничениями от переспама.
4. **P2 (12 страниц) — после P1**, в том же порядке приоритета из вкладки «План внедрения». Страницы
   `future:/mirovaya-literatura` и `proposed:/skazki` требуют сначала публикации страницы, потом SEO.
5. **Ссылочный профиль** — рекомендация агентства («тематические/партнерские размещения») не расписана
   по конкретным донорам, это скорее направление, чем готовый план — не первоочередное.
6. Перед тем как отчитываться числами дашборда заказчику — уточнять, из какого блока цифра (см. раздел 2.3),
   и иметь в виду, что «текущий» период дашборда фактически заморожен на конец июля, а не «сейчас».
