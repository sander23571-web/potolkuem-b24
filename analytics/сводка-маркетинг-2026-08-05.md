**Наценка на посевах** (Мельников/ВК-adblogger, все 5 подтверждённых месяцев, агрегированно): **37,4%** — стабильно, не случайность одного месяца (Фев 40,0% / Март 32,8% / Апрель 37,2% / Май 45,0% / Июль 31,9%).

**Контекст рынка**: типичный retainer агентства при бюджете такого масштаба (~1,04М₽/мес) — 10–15% оборота (100–150к/мес); у нас фикс 230к/мес = 22%. Комиссия за инфлюенсер-посевы обычно 15–25%, до 30% на верхней границе; у нас ~37–40% — выше типичного диапазона, и это ПОВЕРХ уже оплачиваемого фикса.

**Готовые аргументы для разговора с Мельниковым** (задача #26):
1. Соразмерен ли фикс 230к/мес бюджету ~1М/мес?
2. Обоснована ли наценка ~37–40% на посевах сверху фикса?
3. ТЕЛЕКОТ: что реально произошло в феврале/марте/июле — деньги переведены, отчёта о расходовании нет.

## 5. Структурная находка: доступ к Директу

Аккаунт Директа (`e-17441722`) — **`Type: SUBCLIENT`** (подтверждено `clients.get`), не самостоятельный кабинет. Реальным балансом управляет агентство. Это объясняет, почему master-auto кампании (например «Диалекты») показывают реальные показы/клики, но `Cost=0` в нашем API — расход списывается на стороне агентского баланса, нам не виден.

**Важно для интерпретации любых будущих цифр расхода из Директ API**: `Cost=0` не значит «кампания бесплатная» — значит «мы не видим, кто платит».

### Отдача по кампаниям (реальные данные из Метрики, не из отчёта Директа)

Деньги, которые мы **видим и контролируем** (`a2_ptl_club_search`), дают **самую слабую** отдачу (0,08% конверсия в корзину). Деньги, которые мы **не видим** (`a2_ptl_dialekti_master-auto`), дают **лучшую** отдачу (1,27% конверсия, единственная кампания с подтверждёнными возвратами из ЮKassa). Это ключевой контринтуитивный вывод сессии — теперь автоматически отслеживается через СП 1094.

## 8. Процессные уроки — зафиксированы в CLAUDE.md (грабли #20–23)

1. **Пагинация**: `crm.item.list` без явного листания молча обрезает на 50 записях — дважды приводило к неверным выводам. Решение: `scripts/b24_fetch_all.py` — использовать вместо самодельного curl/urllib.
2. **«Задокументировал» ≠ «внёс в CRM»**: находки в `.md`-файле + git-коммит дважды по ошибке воспринимались как «сделано». Решение: для находок с действием — отдельный TaskCreate-таск, закрывать только по прямой проверке в системе.
3. **Маленькая выборка ≠ финальный результат**: процент на 2 месяцах пришлось пересчитывать на 5 после уточнения владельца. Решение: всегда указывать N при выдаче расчётных показателей.
4. **Не доверять собственным более ранним выводам без перепроверки** — особенно в длинных сессиях с несколькими похожими волнами находок.
