# Дашборд маркетинга vs Реестр платежей — диагностика расхождения

*09.09.2026. Задача: свести расходы дашборда `/report/marketing/expenses` к единому источнику —
СП «Реестр платежей» (CRM_32, entityTypeId=1080), вместо нынешнего СП «Расходы» (CRM_24,
entityTypeId=1070). Ниже — что нашлось при сверке и почему прямая замена источника без разбора
кодов даст неверную (завышенную) цифру.*

## 1. Текущий источник дашборда

`report-app/marketing-data.js` берёт расходы из **СП «Расходы» (1070)**, фильтр
`ufCrm24Direction=226` («Маркетинг»), канал (Директ/VK/Посевы/Агентство/SEO/Другое) — из поля
`ufCrm24Channel`. Это **176 записей**, период май 2025 — июль 2026, сумма **12 367 099 ₽**.

Записи введены вручную по нескольким постоянным подрядчикам (ИП Мельников — посевы, ТЕЛЕКОТ — TG
посевы, СМБ-Сервис — Директ+VK+TG и т.д.) — то есть это узкий ручной срез, не полная выгрузка
платежей.

## 2. Что показывает Реестр платежей (1080)

В 1080 — 2306 записей за весь период (01.2025 — 09.2026), классифицированных по «Справочнику
кодов расходов» (IBLOCK_ID=32, 13 групп). Прямая сумма всех кодов групп 11-13 (наивно — «всё, что
не офис/зарплата/налоги») даёт **86,6 млн ₽** — это в 7 раз больше 1070. Разница объясняется двумя
эффектами, и оба — ловушки, если их не разобрать:

### 2.1 «13.8 Прочее» — мусорная корзина, не маркетинг

225-355 записей (в зависимости от того, применены ли поправки 06.09) и **48-59 млн ₽** — это код
для неопознанных платежей классификатором, **преимущественно кластер стройки/благоустройства**
(см. `talk/CLAUDE.md`, запись про офлайн-аудит 06.09.2026: ООО «Патриарший лес», ООО
«МКБ-Интеграция», ИП Лапенко «СМР» и т.п.), не про маркетинг вообще. Исключается из подсчёта
полностью.

### 2.2 Группа 13 (кроме 13.8) наполовину — не маркетинг, а COGS игр

Проверка живых записей показала: коды **13.3 «Дизайнеры»** (8,2 млн ₽, 149 записей), **13.4
«Типографии (тираж)»** (7,6 млн ₽, 10 записей), **13.7 «Сигнальные образцы»** (1,8 млн ₽, 27
записей) — это **разработка и производство самих игр** (отрисовка персонажей, тираж 2100/5000
экз., тестовые образцы перед печатью), не маркетинговые расходы. Примеры:

- `13.3`: «Отрисовка персонажей», «Потолкуем? Соль Земли», «Разработка дизайн макета» — иллюстраторы/
  разработка контента игр
- `13.4`: «Тираж 2 100 экз. Классика», «Тираж 5000 шт: Диалекты» — печать тиража игр
- `13.7`: «Изготовление образца игры Сказки», «Сигнальные образцы игр: Сомелье, Сказки...» —
  предпечатные тестовые экземпляры

Это себестоимость продукта (COGS), не маркетинг — должно остаться вне дашборда маркетинга (скорее
всего это статья для отдельного дашборда себестоимости/производства, если такой нужен).

## 4. Сведение с текущим дашбордом

| | Записей | Сумма | Период |
|---|---|---|---|
| Дашборд сейчас (1070, direction=226) | 176 | 12 367 099 ₽ | май 2025 — июль 2026 |
| Реестр платежей, уточнённые коды маркетинга (после раздела 5, п.2) | 191 | 17 917 839 ₽ | янв 2025 — сент 2026 |
| **Разница** | | **+5 550 740 ₽ (+45%)** | |

Попытка сматчить конкретные записи 1070↔1080 по сумме (простое совпадение суммы, без учёта
контрагента) нашла совпадение для 114 из 176 записей — но часть совпадений ложные (случайное
равенство сумм у разных контрагентов, например 45 000 ₽ у «Мельников — посевы» совпало с
45 000 ₽ у «АСЦ Брэнд Селект — смарт-терминал», это не одна и та же операция). **Точное построчное
сведение 1070↔1080 не является надёжным и не нужно** — правильный путь не «сверить старые записи
1070 с 1080», а **полностью переключить источник дашборда на 1080** с уточнённой границей кодов
выше — 1070 в этом сценарии становится историческим/устаревшим и может быть выведен из
эксплуатации для раздела «Маркетинг».

Разница +5,17 млн ₽ объясняется тем, что 1070 отслеживал только рекламные каналы (группа 11:
кабинеты + агентство + сайт) — **PR (блогеры/журналы/фото/радио) и продакшн-контент (ролики/
копирайтер/мерч/лифлеты) в 1070 не вводились вообще**, хотя реально оплачивались и есть в банковской
выписке.

## 5. Незакрытые вопросы перед переключением дашборда

1. **7 записей на флаге «требует решения руководителя»** (из офлайн-аудита 06.09), ~660 тыс.₽ —
   ИП Красикова, ИП Дмитриев, Радио-Любовь. **Решено владельцем 09.09.2026: это PR-расходы по
   принятой в компании классификации** (Радио-Любовь = реклама на радио = PR) — включены в сумму
   раздела 3 без исключения. Уже учтены в 17 540 539 ₽ выше (они и раньше входили в код-группы
   11.6/12.2/12.5, просто были помечены «на флаге» — флаг снят по этому классу платежей).

2. **09.09.2026 — доп.проверка по подсказке владельца («в спорных могут быть такие же»)**: полное
   сканирование корзины «13.8 Прочее» (не только 199 вопрос-записей, а все ~193-355 записей кода)
   по ключевым словам рекламы/PR (реклама, СММ, пиар, блогер, инфлюенс, vc.ru, маркетинг, промо)
   нашло **7 дополнительных записей на 377 300 ₽**, которые классификатор пропустил целиком (не
   было даже флага «вопрос») — они физически лежат в мусорной корзине вперемешку со стройкой:

3. **Остаётся один открытый, по-настоящему неоднозначный кластер** — 2 платежа «ООО ЯНДЕКС МАРКЕТ»

   маркетинг), так и комиссия/логистика маркетплейса (тогда нет, это расход канала продаж, не

4. ~~Поправки офлайн-аудита ещё не применены к живым записям~~ — **закрыто 09.09.2026.** По

## Предложение по реализации

Переписать `report-app/marketing-data.js`: заменить фетчер `fetchRawExpenses()` — источник 1070 →
1080, фильтр по `ufCrm32Code` с картой кодов из раздела 3 (с применением `overrides.json` поверх
живых значений, по аналогии со скриптом аудита), период — по полю `begindate` записи 1080 (это
реальная дата платежа, не `closedate` — см. грабли в `talk/CLAUDE.md` п. про СП Реестр платежей).
Канал/статья для агрегации по каналам на дашборде — сделать по коду (11.1→Директ? нет — коды 11.1/
11.2/11.3 это кабинеты СМБ/ВК/Телекот, не соответствуют текущим CHANNEL_LABELS напрямую, нужно
новое сопоставление код→канал или показывать сразу по кодам классификатора, что содержательно
понятнее).
