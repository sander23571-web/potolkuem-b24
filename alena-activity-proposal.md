# Работа креативного директора Алёны — предложение по параметрам (24.08.2026)

> Вырос из пункта бэклога «система задач написания статей и отражения в календаре» — владелец
> уточнил, что нужен полноценный охват всей активности Алёны, 4 блока. Ниже — только
> предложение по параметрам каждого блока, **изменения в Б24 не вносились**.

> ⚠️ **Не путать с дашбордом «Активность»** (`/tasks`, бывший «Задачи») — это отдельный,
> общекомандный дашборд (сейчас задачи Б24, предложен блок «Договоры», см. BACKLOG.md п.17),
> не посвящённый одной Алёне. Смарт-процесс(ы) из этого файла — источник данных, который со
> временем МОЖЕТ стать ещё одним блоком на дашборде «Активность» (по тому же принципу, что и
> Договоры), но это отдельное решение, не подразумевается автоматически.

## Общие поля (предлагаю одинаковые во всех 4 блоках)

- Дата дедлайна / дата факта
- Статус — единая шкала стадий, но с точками входа под специфику блока (см. ниже у каждого)
- Ответственный (по умолчанию Алёна — на случай, если позже подключится ещё кто-то)
- Приоритет
- Комментарий
- Файлы (материалы/результат)

## 1. Соцсети (посты и размещение информации)

- Платформа — можно переиспользовать enum, который уже есть в СП «Статистика площадок»
  (VK/TG/Дзен/MAX и т.п.), не заводить новый список с нуля
- Дата публикации
- Тип контента (пост / сторис / рилс / карусель)
- Тема / заголовок
- Статус (в разработке → на согласовании → запланировано → опубликовано)
- Ссылка на публикацию
- Прикреплённые материалы

**Отдача (25.08, по просьбе владельца — «нужно и отдачу зафиксировать»)**, два варианта:

- **Вариант A, рекомендую:** поле-ссылка на соответствующую запись СП «Статистика площадок»
  (1074) — там уже считаются охваты/просмотры/вовлечённость по платформе и периоду (в т.ч.
  `ufCrm28Reach`, `ufCrm28Er`). Не дублировать цифры руками — просто видно, что у поста есть
  привязанная статистика, кликнуть и посмотреть актуальные цифры там же.
- **Вариант B, проще для ручного ввода:** прямые поля **Охват** и **Просмотры** прямо в
  карточке поста здесь. Быстрее завести, не нужна связка с другим СП — но цифры придётся
  вписывать руками, и они будут расходиться с реальной статистикой площадок, если её не
  обновлять синхронно.

## 2. Статьи журнала

- Заголовок
- Тема / рубрика
- Дедлайн публикации / дата публикации
- Статус (идея → черновик → редактура → готово → опубликовано)
- Ссылка на публикацию
- Автор текста (на случай, если не всегда Алёна)
- Ключевой SEO-запрос (опционально — связка с существующим SEO-модулем в маркетинговом
  дашборде, если статьи пишутся под конкретные запросы)
- Файл черновика

**Отдача:** если статья публикуется на сайте — просмотры страницы уже видны в Яндекс.Метрике
по адресу страницы; можно вывести на дашборде число визитов за период по URL статьи (данные
есть, метод уже используется для SEO-раздела), без ручного ввода.

## 3. Дизайнерская активность

- Тип работы (макет / баннер / упаковка / полиграфия / иллюстрация и т.п.)
- Назначение — для чего делается; если это под конкретную выставку/магазин/расход, разумно
  сослаться на существующую запись (СП «Выставки», «Магазины», «Расходы»), не дублировать
  контекст текстом
- Дедлайн
- Статус (эскиз → правки → финал → в печать/выгружено)
- Файлы (макеты)
- Затраченное время — опционально, если важно для оценки нагрузки на Алёну

## 4. Съёмка (фото и видео)

- Тип съёмки (продуктовая / событийная / портретная / видео)
- Дата съёмки
- Повод/объект — тоже разумно связать с существующей записью (например, съёмка на конкретной
  выставке — сослаться на СП «Выставки»), а не дублировать
- Статус (запланировано → отснято → в обработке → готово)
- Объём отснятого (фото шт. / видео мин.)
- Ссылка на исходники / готовый материал (облако)
- Где использовано (соцсети / сайт / каталог) — постфактум, для понимания жизненного цикла
  материала

**Отдача:** если материал в итоге ушёл в пост/рилс — отдельно её не считать, а сослаться на
запись блока «Соцсети», где уже будет охват/просмотры (вариант A/B выше). Съёмка сама по себе
охвата не имеет, только через то, где её потом использовали.

## Открытый архитектурный вопрос — как это завести в Б24

Два варианта, оба рабочие, разница — в администрировании:

- **Один смарт-процесс «Активность Алёны», 4 категории (воронки)** — по одной на блок, как
  уже сделано в проекте для похожих доменов (одна сущность, несколько направлений через
  categoryId). Плюс: один пункт меню, общие сквозные поля видно сразу. Минус: у полей разных
  блоков мало общего (тип съёмки ≠ тип поста), в интерфейсе будут не всегда релевантные поля.
- **4 отдельных смарт-процесса.** Плюс: у каждого только свои поля, чище интерфейс. Минус:
  4 отдельных пункта меню/настройки вместо одного, административно тяжелее.

Отдельно от выбора архитектуры — вопрос про **календарь**: и это, и снятая ранее со списка
синхронизация Яндекс.Календаря затрагивают одну и ту же тему (дедлайны/публикации, видимые в
календаре Б24) — возможно, разумно решать оба вопроса вместе, а не по отдельности.

**Ничего из этого не создано в Б24** — жду решения по параметрам и архитектуре.
