# Примеры автоматизации — «Потолкуем?»

> Три практических примера: настройка роботов в интерфейсе Битрикс24 и webhook-скрипт.
> Роботы настраиваются без кода. Webhook-скрипт — для внешнего сервера (например, n8n или Python).

---

## Автоматизация 1: Новый лид с выставки → задача менеджеру

**Сценарий:** амбассадор собрал контакт через планшетную форму → лид создан →
менеджер получает задачу «Позвонить в течение 24 часов».

**Тип:** Робот в CRM (Лиды)

### Где настраивать

**CRM → Лиды → шестерёнка (Настройки) → Роботы и триггеры**

Откроется конструктор воронки лидов. Найдите стадию **«Новый»**.

### Настройка робота

1. Нажать **«Добавить робота»** на стадии **«Новый»**
2. Выбрать → **«Создать задачу»**
3. Заполнить:

| Параметр | Значение |
|---|---|
| Название задачи | `Первый звонок: {lead_name}` |
| Описание | `Источник: Выставка. Связаться в течение 24 часов. Телефон: {lead_phone}` |
| Ответственный | Менеджер продаж |
| Срок | +1 день от создания лида |
| Привязать к CRM | Да (к текущему лиду) |

4. **Условие запуска:** поле `SOURCE_ID` = «Выставка»

> Так задача создаётся только по лидам с выставки, а не по всем подряд.

5. Сохранить.

### Результат

Каждый новый контакт с планшета → задача менеджеру с именем, телефоном и дедлайном.
Лид не потеряется.

## Автоматизация 2: Получен отчёт амбассадора → уведомление в чат

**Сценарий:** амбассадор заполнил форму → в «Мероприятиях» создан новый элемент →
менеджер получает уведомление в Битрикс24-мессенджере.

**Тип:** Робот в смарт-процессе «Мероприятия»

### Где настраивать

**CRM → Мероприятия → шестерёнка → Роботы и триггеры**

Найдите стадию **«Новое»** (первая стадия воронки Мероприятий).

### Настройка робота

1. **«Добавить робота»** → **«Отправить сообщение»** (или **«Уведомление в мессенджере»**)
2. Заполнить:

| Параметр | Значение |
|---|---|
| Получатель | Ответственный менеджер |
| Текст | `Новый отчёт: {title}. Амбассадор: {assigned_name}. Оценка: {UF_CRM_7_RATING}. Продано: {UF_CRM_7_SALES_COUNT} шт.` |

3. **Задержка:** без задержки (сразу при создании)
4. Сохранить.

### Альтернатива: уведомление в Telegram

Если менеджер предпочитает Telegram — подключить через **«Контакт-центр → Telegram»**
и выбрать канал в роботе «Отправить сообщение».

### Результат

Менеджер видит сводку по каждому мероприятию в реальном времени — не нужно заходить в CRM самому.

## Автоматизация 3: Webhook — низкий остаток на точке продаж

**Сценарий:** менеджер обновил поле «Остаток на точке» (`UF_CRM_11_STOCK_CURRENT`) →
если значение < 3, автоматически создаётся задача на поставку.

**Тип:** Исходящий webhook (Битрикс24 → внешний скрипт) + REST API обратно в Б24.

### Шаг 1: Настроить исходящий webhook в Битрикс24

**Настройки (шестерёнка справа вверху) → Разработчикам → Исходящие вебхуки**

Добавить webhook:
- **Обработчик:** `https://ваш-сервер/b24-stock-alert` (URL вашего скрипта)
- **Событие:** `ONCRMSMARTPROCESSITEMUPDATE` — обновление элемента смарт-процесса

> Можно использовать бесплатный n8n (self-hosted) или Make.com вместо своего сервера.

### Шаг 2: Обработчик (Python / n8n)

```python
# b24_stock_alert.py
# Запускать как Flask/FastAPI endpoint или через n8n Python-функцию

import json
import urllib.request

WEBHOOK = "https://b24-0l7a4f.bitrix24.ru/rest/1/nf1gntfiteqiazcc"
ENTITY_TYPE_TOCHKI = 1042   # entityTypeId Точки продаж
STOCK_FIELD = "UF_CRM_11_STOCK_CURRENT"
LOW_STOCK_THRESHOLD = 3
MANAGER_ID = 1              # ID ответственного в Б24

def call(method, params):
    url = f"{WEBHOOK}/{method}"
    data = json.dumps(params).encode()
    req = urllib.request.Request(
        url, data=data, headers={"Content-Type": "application/json"}
    )
    with urllib.request.urlopen(req) as r:
        return json.loads(r.read())

def handle_webhook(event_data):
    """Вызывается при получении события от Битрикс24."""
    item = event_data.get("data", {}).get("FIELDS", {})
    entity_type = int(item.get("ENTITY_TYPE_ID", 0))

    # Проверяем, что это элемент Точек продаж
    if entity_type != ENTITY_TYPE_TOCHKI:
        return

    item_id = item.get("ID")
    stock = item.get(STOCK_FIELD)
    if stock is None:
        return

    stock = int(stock)
    if stock >= LOW_STOCK_THRESHOLD:
        return  # Всё в порядке

    # Получаем название точки
    resp = call("crm.item.get", {
        "entityTypeId": ENTITY_TYPE_TOCHKI,
        "id": item_id
    })
    title = resp.get("result", {}).get("item", {}).get("title", f"ID {item_id}")

    # Создаём задачу
    call("tasks.task.add", {
        "fields": {
            "TITLE": f"Низкий остаток: {title} — осталось {stock} шт.",
            "DESCRIPTION": (
                f"На точке '{title}' остаток упал до {stock} шт. "
                f"(порог: {LOW_STOCK_THRESHOLD}). Нужна поставка."
            ),
            "RESPONSIBLE_ID": MANAGER_ID,
            "DEADLINE": "",   # Без дедлайна — срочно
            "UF_CRM_TASK": [f"T_{ENTITY_TYPE_TOCHKI}_{item_id}"]  # Привязать к точке
        }
    })
    print(f"Задача создана: низкий остаток на '{title}' ({stock} шт.)")
```

### Шаг 3: Как проверить

1. Открыть любую точку продаж в CRM
2. Изменить поле «Остаток на точке» на значение `2`
3. Сохранить → в течение нескольких секунд должна появиться задача

### Упрощённый вариант без внешнего сервера

Если внешний сервер не нужен — использовать робот с проверкой условия:

**CRM → Точки продаж → Роботы** → стадия «Активна» →
**«Создать задачу»** с условием: `UF_CRM_11_STOCK_CURRENT` меньше `3`.

> Робот срабатывает при смене стадии, а не при изменении поля.
> Для мгновенной реакции на изменение поля нужен webhook.

## Итого

| Автоматизация | Тип | Сложность |
|---|---|---|
| Задача менеджеру при лиде с выставки | Робот в CRM (без кода) | Простая |
| Уведомление при новом отчёте амбассадора | Робот в смарт-процессе (без кода) | Простая |
| Задача на поставку при низком остатке | Webhook + скрипт | Средняя |

**Рекомендация для старта:** настроить первые две автоматизации через интерфейс.
Webhook добавить по мере роста — когда появится n8n или аналог.

---

*Все методы REST: `tasks.task.add`, `crm.item.get` — из той же webhook-точки.*
