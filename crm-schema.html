Пояснения по связям

🎪 Выставка — центральный хаб

  • К ней привязаны: Выходы, Расходы, Игровые сессии, Логистика
  • Сделки выставки ссылаются на неё через PARENT_ID_1048
  • Сделки + Выходы также ссылаются на Ведущего через PARENT_ID_1052

🎤 Ведущий — профиль и связи

  • Связан с Контактом через contactId
  • Один ведущий → много Выходов (через parentId1052 на Выходе)
  • Один ведущий → много Игровых сессий (через parentId1052 на Сессии)
  • Сделки ведущего видны через PARENT_ID_1052 на Сделке

📝 Сделки — воронки и поля

  • Кат. 18 — розница: онлайн-заказы, выставочные продажи
  • Кат. 24 — оптовые покупатели (B2B)
  • Кат. 26 — B2C мероприятия (открытые игры)
  • Кат. 28 — Ателье (производство игр)
  • Кат. 30 — B2B корпоративы
  • В каждой сделке — товарные позиции из каталога (резервируют склад)

📦 Склад и каталог

  • 25 товаров (игр) в каталоге
  • 12 складов: 2 собственных, 1 WB, 7 точек продаж, 1 выездной, 1 кластер
  • Остатки: только склады 4, 6, 8 заполнены (итого ~10 117 шт.)
  • Добавление товара в сделку → автоматический резерв на складе
  • Метод списания: FIFO

🔐 Согласия 152-ФЗ

  • Создаются через CardScanner (QR-токен) или consent-service
  • Привязываются к Контакту через contactId
  • Без связей с другими смарт-процессами (изолированная сущность)

⚠️ Важные особенности API

  • PARENT_ID_1052 в Сделке — только через crm.deal.update, не через add
  • parentId1052 camelCase в crm.deal.add — молча игнорируется
  • Смена воронки сделки (CATEGORY_ID) через API не работает
  • Игровая сессия: ведущий — родитель сессии (с 19.06.2026), не наоборот
