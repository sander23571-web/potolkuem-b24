# Активность Алёны — техническая спецификация для создания в Б24 (29.08.2026, v2)

> Версия 2 — переписана по прямым правкам креативного директора (Алёны) к первой версии.
> Ничего в Б24 ещё не создано — это спецификация к утверждению, готова к исполнению по одному
> подтверждению.

---

## Архитектура (без изменений)

Один смарт-процесс «Активность Алёны», 4 категории: **Соцсети / Журнал «Потолкуем?» /
Дизайнерские работы / Съёмки** (переименовал блоки под её терминологию). `typeId`/`entityTypeId`
присвоятся автоматически при создании.

## Общие поля (подтверждены без изменений)

Дата (`begindate`) / Статус (`stageId`) / Ответственный (`assignedById`, по умолчанию Малькова
Алёна, id=104) / Комментарий (UF string) / Файлы-материалы-результат (UF file, multiple).
**Приоритет** — оставляем как необязательное поле (enum Низкий/Средний/Высокий), заполняется
только там, где реально нужен, технически ничего не меняется — поле и так не обязательное.

## 1. Соцсети

**Поля:** Платформа (enum) · Дата публикации (date) · Тип контента (enum: пост/сторис/рилс/
карусель) · Тема/заголовок (string) · Ссылка на публикацию (url) · Прикреплённые материалы (file)

**Статус — упрощён по её просьбе:** 2 стадии вместо 4 — `Черновик` → `Опубликовано`
(записи по факту уже опубликованного контента можно сразу заводить в финальной стадии).

### Статистика — проверил LiveDune API прямо сейчас, ответ конкретный

Дёрнул `/accounts/{id}/posts` для всех 5 площадок проекта (VK, Telegram, Дзен, MAX, TikTok) —
у каждой уже есть **пер-постовая** статистика, ключ сопоставления — `url`, который у поста в
LiveDune совпадает с полем «Ссылка на публикацию»:

| Площадка | Что реально отдаёт LiveDune (проверено) |
|---|---|
| VK | `impressions.total` (просмотры), `reach.total` (охват), `reactions.likes/comments/reposts/shares` |
| Telegram | `impressions.total` (просмотры), `reactions.likes/comments/forwards` — **есть именно «пересылки», как ты просила** |
| Дзен | `impressions.total`, `reactions.likes/comments/reposts` — **но НЕ найдено** дочитываний/среднего времени чтения/досмотров в этом эндпоинте (см. ограничение ниже) |
| MAX, TikTok | `reactions.likes/comments/reposts` — тоже доступно |
| Instagram | **не подключён к LiveDune в этом проекте вообще** (аккаунта нет в списке отслеживаемых) — если ты реально публикуешь в Instagram, для него автоматика невозможна без отдельной интеграции, только вручную |

**Вывод: автоподтягивание в целом возможно** для VK/Telegram/Дзен/MAX/TikTok — просмотры/охват/
реакции/репосты-пересылки. Технически: понадобится отдельный небольшой скрипт-синхронизатор
(по образцу уже существующего `scripts/platform-stats-cron.py`), который по URL из записи находит
соответствующий пост в LiveDune и подтягивает цифры — **это отдельная разработка после создания
самого СП**, не входит в «просто завести поля».

**Ограничение по Дзен:** дочитывания / среднее время чтения / среднее время просмотра / досмотры
в проверенном эндпоинте не нашлись — либо это в другом эндпоинте LiveDune (`/analytics`, не
проверял детально), либо в принципе не отдаётся по API. Пока закладываю эти 4 показателя как
**поля с ручным вводом** (задел на будущее, если найдётся способ автоматизировать — не пересоздавая
структуру).

**Поля статистики (общие + Дзен-специфика), с автозаполнением где возможно + ручной правкой всегда доступной:**

| Поле | Тип | Авто (после доп. разработки) |
|---|---|---|
| Просмотры | double | VK/TG/Дзен/MAX/TikTok |
| Охват | double | VK |
| Реакции | double | все |
| Репосты / Пересылки / Сохранения | double | все (репосты/forwards) |
| Дочитывания, % (Дзен, статьи) | double | нет — вручную |
| Среднее время чтения (Дзен, статьи) | string | нет — вручную |
| Среднее время просмотра (Дзен, видео) | string | нет — вручную |
| Досмотры, % (Дзен, видео) | double | нет — вручную |
| Скриншот полной статистики | file | — (всегда вручную, как подстраховка) |

## 2. Журнал «Потолкуем?» (переименован из «Статьи журнала»)

**Структура по образцу твоего редакционного календаря:**

| Поле | Тип |
|---|---|
| Дата (план публикации) | `begindate` (штатное) |
| Копирайтер | employee |
| Тема статьи | string |
| Рубрика | string |
| Статус | `stageId`, новая воронка ниже |
| Фактическая дата публикации | `closedate` (штатное) |
| Ссылка на статью | url |
| Автор текста | employee (отдельно от Копирайтера — оставлен по твоей просьбе) |
| Просмотры страницы (Метрика) | double — остаётся |
| Компьютерная версия сайта | boolean (да/нет) |
| Мобильная версия сайта | boolean (да/нет) |
| Яндекс.Дзен | boolean (да/нет) |

**Убрано:** SEO-запрос.

**Статусы (новые, 6 стадий):**
`Запланирована` → `В работе у копирайтера` → `Сдана редактору` → `Проверена` → `Визуалы готовы`
→ `Опубликована`

## 3. Дизайнерские работы

**Тип работы (расширенный список):**
Презентация / Выставочный материал / Полиграфия / Рекламный креатив / Генерация изображений /
Материал для сайта / Другое

**Добавлено:**

| Поле | Тип |
|---|---|
| Проект / направление | string |
| Исполнитель | string (не завязано на пользователя Б24 — часто внешние подрядчики, см. находку 29.08 по «Штатной структуре» — Разумкова/Кардаков/Цейтлин/Буравлева не заведены как пользователи) |
| Ссылка на итоговый файл | url (если файл хранится не в Б24; если в Б24 — использовать общее поле «Файлы») |
| Расходы (при наличии) | double |

**Убрано:** Затраченное время.

**Статусы (упрощены до 4):** `Поставлена` → `В работе` → `На согласовании` → `Готово`

## 4. Съёмки

**Тип съёмки (обновлён):** Фотосъёмка / Видеосъёмка / Выезд контент-мейкера / Монтаж

**Оставлено:** Где использовано (enum multiple: Соцсети/Сайт/Каталог).

**Добавлено:**

| Поле | Тип |
|---|---|
| Исполнитель / подрядчик | string |
| ТЗ / ссылка на ТЗ | url |
| Стоимость работы | double |
| Договор (при наличии) | file |
| Объём результата | string (свободный формат: «12 роликов, 45 фото, 8 исходников») |

**Статусы (новые, 5 стадий):**
`Запланировано` → `ТЗ готово` → `В работе` → `Материал получен` → `Готово`

### Расходы по съёмкам — отдельный запрос

Ты попросила видеть **за месяц общую сумму расходов на съёмки**, с возможностью провалиться в
конкретные работы («Исполнитель → Работа → Стоимость»). Поле «Стоимость работы» на каждой записи
уже даёт для этого все данные — сама помесячная сводка технически не требует новых полей, два
варианта её получить:

- **Сразу и бесплатно:** нативный фильтр/список Б24 по категории «Съёмки» за период с суммой по
  колонке «Стоимость работы» — работает сразу после создания СП, без доп. разработки.
- **Отдельная карточка на дашборде** (по образцу уже существующих `/report/marketing/expenses`,
  `/report/realization`) — красивее и с диаграммой по месяцам, но это отдельная разработка после
  того, как СП поживёт и наберёт данные.

   важны — отдельное решение (нужен ли Instagram в LiveDune вообще, это платный трекинг).

## Порядок создания (без изменений от v1)

1. `crm.type.add` → typeId/entityTypeId.
2. `crm.type.update` → `isUseInUserfieldEnabled: "Y"`.
3. Переименовать стадии категории 1 (Соцсети) + добавить категории 2-4 со своими стадиями.
4. Создать UF-поля по таблицам выше.
5. Сверить вживую (`crm.item.fields`, `crm.status.list`), задокументировать в
   `b24-api-patterns.md`/`talk/CLAUDE.md`.
